Kahn1 is an open-source decision engine built on a fine-tuned Qwen2.5-3B. Give it a state (a message, a review, a document) and a list of typed questions. Each answer comes back as a value and a calibrated probability distribution, read straight from the logits of the option tokens. Nothing is generated and nothing is parsed, so a malformed answer cannot happen.

How it works

The name is a nod to Daniel Kahneman's System 1: fast, cheap judgments that settle most cases and route the rest before a slower System 2 (a frontier model or a person) steps in.

STATE tokens

KV CACHE · COMPUTED ONCE, SHARED BY EVERY QUESTION
TOKENS GENERATED 0 FORWARD PASSES 0

Recorded outputs of the v3 checkpoint (temperature calibration, k = 1). Each column is the probability of one option token: nothing else is read, nothing is written.

01

State + typed questions

You send one state and any number of questions, in the JEV schema format or the native API. Options are listed under letters A, B, C… so every answer is a single token.

02

One batch, one shared prefix

All questions, and their option permutations, go to vLLM in one batch. They share the state's KV cache (prefix caching), so ten questions cost little more than one.

03

Read the logits

Kahn1 takes the softmax over the option tokens only, averages it across option orders to cancel position bias, then applies temperature calibration. No text is generated.

Three primitives

Choice

Pick one option, with an optional none of these answers fallback. Up to 26 options in one pass; larger label sets go through a two-stage router.

{"choice": "refund", "confidence": 0.95,
 "probabilities": {…}}

Score

Place the state on an ordered scale. Besides the level, the expected value Σ i·pi gives a continuous score between levels.

{"level": "high", "score": 2.26,
 "confidence": 0.65, "probabilities": {…}}

Noul

Is this statement true for the state? A yes/no question answered with a probability you can threshold.

{"noul": 0.98}

Confidence is (p_max − 1/n) / (1 − 1/n): the distance from a uniform guess, not the probability of being right. Schema compatibility: the server accepts JEV dictionaries on POST /v1/evaluate/jev.

Use cases

Kahn1 is meant to be the fast first layer of a pipeline: it takes the routine decisions and hands the rest to something slower and more expensive.

01

Triage and routing

Sort tickets, emails or claims by intent, urgency and risk in one pass. To change the categories, edit the schema: no relabelling, no retraining.

02

Guardrails for agents

Before a tool call runs, ask yes/no questions about it: does it leak personal data, does it break a policy, did the user approve it? Each answer is a probability you can gate on.

03

Document scoring

Rate tone, urgency, complexity or quality as continuous expected values rather than coarse labels, and index documents on them.

04

Selective escalation

Automate the confident cases and send the rest to a larger model or a person. With calibrated confidence, the threshold becomes a risk decision you can measure.

05

Cold start

A new product line or a new taxonomy works zero-shot on day one. Recalibrate on your own labelled examples with sysone calibrate once you have them.

06

Control loops

One Choice per tick can drive a policy: Kahn1 plays Snake as well as a greedy heuristic, provided the state spells out what lies around the head.

Pick classical ML when the ontology is fixed for years, latency must stay under 5 ms, hardware is small or the data is tabular. Pick Kahn1 when categories change often, when you start without labels, or when the signal is in free text.

Caveats

Kahn1 is a 3-billion-parameter model. Read this before putting it in front of real decisions.

  1. It is not a frontier model.

    On subjective or ambiguous judgments it is wrong more often than a large model. On the hard tier of the external JevBench it gets 42% right, against 73% for Jev.

  2. Accuracy depends on the primitive.

    Choice is strong (91% on held-out intent sets). Score reaches 51 to 52% exact match on 5-level scales, 95% within one level on SST-5. Noul is the weak point: 83% on RTE, 65% on SciTail (out-of-domain science entailment).

  3. Calibration holds on its own distribution.

    Temperatures were fitted on a split disjoint from training, not on your data, and Noul's calibration error is still 0.23. Recalibrate on your domain before trusting a threshold.

  4. Confidence is not the probability of being right.

    It measures the distance from a uniform guess. Set thresholds on held-out data from your domain and check the risk-coverage curve.

  5. Deterministic computation is not deterministic truth.

    Same weights, same prompt and same kernels give the same logits. That does not make the answer correct: adversarial or out-of-distribution text can still fool it, and it offers no formal guarantee.

  6. Regulation still applies.

    Reading logits instead of parsing JSON removes format errors, not the obligations that come with using a neural model for decisions (EU AI Act, sector rules). Keep a person or a larger model on the low-confidence path, and log what was decided.

  7. The speed comes from engineering.

    Prefix caching and a single output position explain the latency, not a new architecture. On a CPU expect seconds per question; in a browser without WebGPU, minutes.

  8. The browser demos run an older checkpoint.

    The playground and Snake load a v1 GGUF quantized to 4 bits (thanks to mradermacher); the page flips its Noul answers, which v1 learned inverted. The benchmarks below are the unquantized v3 checkpoint on vLLM.

FAQ

What is Kahn1?
An open-source decision engine built on a fine-tuned Qwen2.5-3B. It takes a text (the state) and typed questions, and returns for each question a typed value and a calibrated probability distribution read from the logits of the option tokens. It generates no text.

How is it different from JSON mode or structured outputs?
Structured decoding constrains the tokens a model generates, and the result still has to be parsed. Kahn1 generates nothing: it reads one probability distribution per question over the option tokens, so every answer comes with its full distribution and a calibrated confidence, and there is nothing to parse.

Can it run without a GPU?
Yes. The CPU engine runs the same decision code with a plain transformers forward pass, at seconds per question instead of tens of milliseconds. The playground and Snake also run a 4-bit GGUF in your browser with WebGPU; without WebGPU they fall back to the CPU, which takes minutes.

Can I use my own categories?
Yes. Categories, scales and statements are part of each request, so changing them needs no retraining. Calibration was fitted on the training distribution: recalibrate on your own labelled examples with sysone calibrate before relying on a confidence threshold.

How accurate is it?
On 14,663 held-out items: 70.3% overall, 90.9% on Choice, 51.5% exact match on 5-level Score scales (95.2% within one level on SST-5) and 67.0% on Noul. See the benchmark results and the caveats.

How does Kahn1 compare with JEV?
On the 14,663 items of the Kahn1 held-out set, run through the TypeSafe API, Kahn1 scores 70.3% and JEV 1.13.0 67.3%: Kahn1 leads on Choice, they are level on Score and JEV leads on Noul. On the 231 public JevBench items, scored by JevBench itself, Jev scores 86.6% and Kahn1 67.5% (73.0% vs 42.3% on the hard tier). Kahn1 is stronger overall on the task families it was trained for; Jev is clearly stronger on open-ended judgment. Kahn1 is open and runs on your own hardware; JEV is a hosted API. See the head-to-head.

Does the playground send my text anywhere?
No. In WebGPU mode the model runs in your tab; in server mode the page talks only to the server URL you set. Visits are counted by GoatCounter, without cookies, and by Google Analytics only if you accept its cookies.

Is it free?
Yes. The code is MIT-licensed and the weights are on Hugging Face, as a merged model and as a LoRA adapter.
